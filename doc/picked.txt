==============================================================================
1. INTRODUCTION                                           *picked-introduction*

picked.nvim provides a dedicated Source Control view and the operations around
it: staging at file, hunk and line granularity; diffs that always name both
sides; commit, branch, stash, log, blame and conflict resolution; and the
network operations that tie them together.

It is built from Neovim primitives — buffers, windows, extmarks, signs,
keymaps, autocommands and async jobs. Every panel is an ordinary buffer, so
motions, searching, `:wincmd`, window pickers and terminal resizing all behave
exactly as they do everywhere else.

Two properties are treated as non-negotiable:

  * Every action is reachable from the keyboard. Mouse support is additive.
  * Destructive operations require confirmation and say what will be lost.

==============================================================================
2. REQUIREMENTS                                           *picked-requirements*

  Neovim   0.10 or newer      (vim.system, vim.uv, extmark signs)
  git      2.20 or newer      (2.23+ recommended for switch/restore)

No other plugin is required. Nerd fonts are optional: picked probes for glyph
support and falls back to ASCII, and never communicates state with colour
alone, so the interface remains legible in a monochrome terminal.

Run |:PickedHealth| to verify your environment.

3. INSTALLATION                                           *picked-installation*

With lazy.nvim: >lua

    {
      "samirlmahdy/picked.nvim",
      cmd = { "Picked", "PickedOpen", "PickedToggle", "PickedLog" },
      keys = {
        { "<leader>gs", "<cmd>PickedToggle<cr>", desc = "Source Control" },
      },
      opts = {},
    }
<
With packer.nvim: >lua

    use({
      "samirlmahdy/picked.nvim",
      config = function()
        require("picked").setup({})
      end,
    })
<
With vim-plug: >vim

    Plug 'samirlmahdy/picked.nvim'
    lua require('picked').setup({})
<
Calling |picked.setup()| is optional — the commands initialise the plugin on
first use — but it is how configuration is applied.

==============================================================================
4. QUICK START                                             *picked-quick-start*

  1. Open a file inside a git repository.
  2. `<leader>gs` opens the Source Control panel.
  3. `j` / `k` to move. Selecting a file shows its diff — added and removed
     lines with + and -, in green and red — while the cursor stays in the
     list. See |picked-config-preview| to change or disable that.
  4. `s` stages, `u` unstages, `x` discards. Inside the diff, `s` stages one
     hunk, or exactly the lines selected in visual mode.
  5. `c` opens the commit editor. Write a message, or press `<C-g>` to ask the
     optional GitHub Copilot CLI for an editable suggestion, then `<C-s>` or
     `:w`.
  6. `p` pushes.
  7. `?` shows every mapping, generated from your configuration.

6. KEYMAPS                                                     *picked-keymaps*

Press `?` in any panel for the authoritative list: it is generated from your
configuration, not from this document.

GLOBAL                                                  *picked-keymaps-global*
                                                        *picked-prefix*
Every global mapping shares one prefix, `<leader>gu` by default.

picked deliberately does not squat on `<leader>g`: distributions such as
LazyVim already own most of it, and a mapping that is silently skipped because
the key was taken is worse than an unfamiliar one. Moving the whole set is one
line: >lua

    require("picked").setup({ prefix = "<leader>gui" })
<
  <leader>guu   Toggle the Source Control panel
  <leader>gud   Diff the current file
  <leader>gub   Branches
  <leader>gul   Commit history
  <leader>guh   History of the current file
  <leader>guc   Commit
  <leader>gup   Push
  <leader>guP   Pull
  <leader>guf   Fetch
  <leader>gus   Stashes
  <leader>guB   Blame the current file
  <leader>gu<space>  Command palette

IN A FILE BUFFER                                        *picked-keymaps-buffer*

  ]c  [c        Next / previous hunk. Inside a window in diff mode these fall
                through to Neovim's own |]c| and |[c|, so picked never shadows
                the builtin motions — including in its own split view.
  <leader>guS   Stage the hunk; in visual mode, the selected lines
  <leader>guU   Unstage the hunk
  <leader>guX   Discard the hunk; in visual mode, the selected lines
  <leader>guv   Preview the hunk
  <leader>guL   Blame the current line

SOURCE CONTROL PANEL                                    *picked-keymaps-source*

  (cursor)      Selecting a file shows its diff (|picked-config-preview|)
  <CR>          Open the file for editing, or expand/collapse the row
  <C-x> <C-v> <C-t>   Open in a split / vsplit / tab
  s  u  x       Stage / unstage / discard
  S  U          Stage everything / unstage everything
  d  D          Diff this entry / diff everything against HEAD
  c  ca  cP     Commit / amend / commit and push
  p  P  f       Push / pull / fetch
  b  l  z       Branches / log / stashes
  B  h          Blame / file history
  o             Open on the remote's website
  yp  yy        Copy absolute / relative path
  za  zA        Toggle this node / everything
  ]f  [f        Next / previous file
  <Tab> <S-Tab> Next / previous section
  R             Resolve the conflict under the cursor
  m             Contextual menu
  /             Filter files
  r  ?  q       Refresh / help / close

`q` closes whichever picked pane holds the cursor, the Source Control panel
included. Dismissing a diff hands your editor window back with the buffer that
was in it: picked borrows that window rather than taking it, so closing a diff
never costs you a window (and never leaves the sidebar alone and stretched).

                                                              *picked-floats*
Floating views dismiss themselves rather than waiting to be told. A float sits
above the editor area, so a diff opened from the history list would otherwise
appear *underneath* the list that launched it — the user asks to see something
and nothing appears to happen.

Anything that occupies the editor area — a diff, a file, a blame column —
closes every picked float first. Opening one float closes any other, so history,
branches, stashes, commit details, help, the output window and contextual menus
never stack; selecting a commit in the history replaces the list with the
commit's details rather than covering it.

Nothing else is affected: the Source Control sidebar is a split, not a float,
and stays exactly where it is.

Visual mode works: select rows and press `s`, `u` or `x`.

DIFF VIEW                                                 *picked-keymaps-diff*

  s  u  x       Stage / unstage / discard the hunk
  s  x (visual) Stage / discard exactly the selected lines
  ]c  [c        Next / previous hunk (in both presentations)
  ]f  [f        Next / previous file
  <Tab>         Switch what is compared: HEAD<->index / index<->worktree
  <C-v>         Switch presentation: unified patch <-> side by side
  <CR>          Open the real file at this line

In the side-by-side view, `]c`/`[c`, folding and |do|/|dp| are Neovim's own
diff-mode behaviour. picked maps nothing on the pane showing your real file —
taking <C-v> from a file buffer would cost blockwise visual mode — so
|:PickedDiffView| is the way back to the unified patch from that side.

LOG                                                        *picked-keymaps-log*

  <CR>          Commit details (replaces the list)
  d             Diff against the parent
  c  v          Cherry-pick / revert
  b  t          Create a branch / tag here
  C  R          Check out (detached) / reset to here
  yy  o         Copy the hash / open on the remote
  L  /          Load more / search messages

BRANCHES                                              *picked-keymaps-branches*

  <CR>          Switch to the branch
  c  R  d       Create / rename / delete
  m  r          Merge into current / rebase onto
  p  f  u       Push / fetch / set upstream
  l  D          History / diff against current
  /             Filter

STASHES                                                  *picked-keymaps-stash*

  <CR>          Inspect
  a  p  d       Apply / pop / drop
  b  c          Branch from stash / create a stash

CONFLICTS                                             *picked-keymaps-conflict*

  o  t  b       Keep ours / theirs / both
  B  n          Keep the merge base / neither
  ]x  [x        Next / previous conflict
  s             Stage the file as resolved

COMMIT EDITOR                                           *picked-keymaps-commit*

  <C-g>         Suggest an editable message with GitHub Copilot CLI
  <C-CR> <C-s>  Commit. `:w` also works and is immune to terminal flow control.
  <C-p>         Commit and push
  <C-a>         Toggle amend
  <C-c> <Esc>   Cancel, keeping the message as a draft

7. CONFIGURATION                                         *picked-configuration*

                                                              *picked.setup()*
require("picked").setup({opts})

Deep-merges {opts} over the defaults. Safe to call more than once. Invalid
values are reported and replaced with the default rather than breaking the
plugin.

Defaults: >lua

    require("picked").setup({
      position = "left",        -- "left" | "right" | "float"
      width = 42,
      compact_width = 34,
      last_window = "keep_width",
      prefix = "<leader>gu",
      auto_refresh = true,
      refresh_debounce = 250,
      file_watch = true,
      timeout = 20000,
      network_timeout = 120000,
      log_level = "warn",
      icons = "auto",
      tree = true,
      tree_flatten = true,
      hints = true,
      default_keymaps = true,
    })
<
                                                       *picked-config-confirm*
`confirm` controls which operations ask first. Setting any entry to `false` is
an explicit opt-in to an unsafe mode. >lua

    confirm = {
      discard = true, discard_hunk = true,
      reset_hard = true, reset_mixed = false, reset_soft = false,
      force_push = true, branch_delete = true, stash_drop = true,
      clean = true, revert = true,
      push = false, pull = false,
    }
<
                                                          *picked-config-diff*
>lua
    diff = {
      context = 3,              -- lines of context in diffs and patches
      algorithm = "histogram",  -- myers | minimal | patience | histogram
      ignore_whitespace = false,
      layout = "vertical",
      preview = "auto",
      preview_delay = 120,
    }
<
                                                       *picked-config-preview*
`diff.preview` decides what selecting a file in the Source Control panel does:

  "auto"    Open its diff in the editor area, keeping the cursor in the
            panel. Selecting a file shows its added and removed lines
            immediately, which is the VS Code behaviour. This is the default.
  "follow"  Only retarget a diff view that is already open; never open one.
  false     Nothing. The diff opens on demand with `d`.

`true` is accepted as a synonym for "auto". `preview_delay` debounces cursor
movement so holding `j` does not queue a diff per row.
                                                        *picked-config-commit*
>lua
    commit = {
      subject_length = 72,
      body_length = 0,
      show_diff = true,
      sign = nil,
      copilot = true,
      copilot_max_diff = 100000,
      copilot_timeout = 120000,
    }
<
`copilot` enables the commit editor's optional GitHub Copilot CLI suggestion
action. The byte limit bounds the staged diff placed in the prompt; oversized
diffs are truncated with an explicit warning in the prompt.

                                                         *picked-config-signs*
>lua
    signs = {
      enabled = true,
      priority = 6,
      watch_buffers = true,
      debounce = 150,
      max_filesize = 2 * 1024 * 1024,
      text = { add = "┃", change = "┃", delete = "▁",
               topdelete = "▔", changedelete = "~", untracked = "┆" },
      ascii_text = { add = "+", change = "~", delete = "_",
                     topdelete = "-", changedelete = "~", untracked = ":" },
    }
<
                                                         *picked-config-blame*
>lua
    blame = {
      enabled = true,
      virtual_text = false,
      virtual_text_delay = 400,
      date_format = "%Y-%m-%d",
      ignore_whitespace = true,
      sync_cursor = true,      -- both panes move together, both directions
      highlight_block = true,  -- the commit's lines, lit in both panes
      color_commits = true,    -- a colour per commit in the blame column
    }
<
                                                        *picked-config-remote*
>lua
    remote = {
      pull_strategy = "ask",        -- merge | rebase | ff-only | ask
      auto_set_upstream = true,
      fetch_prune = false,
      force_push_mode = "with-lease",   -- "with-lease" | "force"
    }
<
`force_push_mode = "force"` is a deliberate downgrade in safety.
`--force-with-lease` refuses to overwrite commits you have not fetched;
`--force` does not.

                                                        *picked-config-browse*
>lua
    browse = {
      opener = nil,     -- nil auto-detects (vim.ui.open, open, xdg-open, ...)
      hosts = {         -- map a self-hosted forge to its URL layout
        ["git.corp.internal"] = "gitlab",
      },
    }
<
Supported layouts: "github", "gitlab", "bitbucket", "gitea", "sourcehut".

                                                   *picked-config-last-window*
`last_window` decides what the sidebar does when it would be the only window
left, which happens the moment you close the last file:

  "keep_width"  Hold the configured width by parking an empty window beside
                it, so the panel never jumps to full screen. This is the
                default. Closing that empty window yourself is respected —
                the panel expands rather than conjuring another one, so `:q`
                keeps working.
  "expand"      Let Neovim stretch the panel across the screen, its default
                behaviour for a lone window.
  "close"       Close the panel as well.

Independently of this, the width is re-asserted after every split and close:
'winfixwidth' limits redistribution but does not pin an exact number, so the
sidebar otherwise drifts a column at a time. A resize you perform yourself is
detected and adopted rather than undone.

                                                       *picked-config-keymaps*
`prefix` sets the leader all global mappings hang off — see |picked-prefix|.

Per-view mappings live under `keymaps.<view>`, where <view> is one of
`common`, `source_control`, `diff`, `log`, `branches`, `stash`, `commit`,
`blame` or `conflict`. A value may be a string, a list of strings, or `false`
to disable the action entirely. >lua

    keymaps = {
      source_control = {
        stage = "<Space>",
        unstage = "<BS>",
        discard = false,
        close = { "q", "<Esc>" },
      },
    }
<
Global mappings live under `global_keymaps` and are installed only when
`default_keymaps` is true. A value there may contain the token `<prefix>`,
which expands to the `prefix` option, so overriding one entry without giving
up the shared prefix is possible: >lua

    require("picked").setup({
      global_keymaps = {
        source_control = "<prefix>g",  -- <leader>gug
        diff = "<leader>D",            -- absolute, ignores the prefix
        blame = false,                 -- not mapped at all
      },
    })
<

picked never overwrites a mapping you already have. A default whose key is
already taken is skipped; |:PickedHealth| lists every such skip.

8. VIEWS                                                         *picked-views*

SOURCE CONTROL                                            *picked-view-source*

The panel answers six questions at a glance: what changed, what is staged,
what is unstaged, what is conflicted, what branch you are on, and what you can
do next.

Moving the cursor onto a file shows its diff in the editor area, with added
and removed lines marked `+` and `-` and highlighted green and red, while the
cursor stays in the panel. `<CR>` opens the file itself for editing. See
|picked-config-preview| to change that.

Sections appear only when they have content: MERGE CONFLICTS, STAGED CHANGES,
CHANGES, STASHES. Changes are shown as a collapsible directory tree
(`tree = false` for a flat list), with chains of single-child directories
collapsed into one row.

Each row shows its status letter first — `M`, `A`, `D`, `R`, `C`, `?`, `U` —
so the view is readable without colour.

On a narrow window the panel drops right-aligned metadata and switches to a
flat list; on a wide one it shows rename sources, per-directory counts and
conflict labels.

DIFF                                                        *picked-view-diff*

Two presentations:

  Unified     Where staging happens. Every row knows its hunk and its position
              in the patch body, so `s` on a hunk and `s` over a visual
              selection both produce an exact patch.

  Side by side  Where reading happens. Built on Neovim's own |:diffthis|, so
              folding, |]c|, |do| and |dp| behave normally.

Choosing between them:

  <C-v>              toggle the diff in front of you, either direction
  :PickedDiffView    the same, and the way back from the split's real-file
                     pane, where picked maps nothing
  :PickedDiff!       open straight into the side-by-side view
  diff.view          "unified" or "split" - what a diff opens as
  diff.layout        "vertical" or "horizontal" - how the split is arranged
  diff.split_full_width
                     give the split the whole editor area (default true)

                                                 *picked-config-split-width*
The two sides each take half of whatever width the sidebar leaves, and are
held there as windows come and go — Neovim otherwise redistributes columns on
every split and close, and the two drift apart.

`diff.split_full_width` is what makes an even half possible. Other ordinary
file windows are closed first, because two panes competing with them end up a
third of the screen each, which is too narrow to read a diff in. Only windows
are closed: with 'hidden' — Neovim's default — the buffers stay loaded and any
unsaved changes survive, and under 'nohidden' a modified buffer's window
refuses to close and simply stays. Floats and picked's own panels are never
touched. Set it false to keep every window and let Neovim divide the space.

'winwidth' widens whichever window holds the cursor by taking columns from
its neighbours, which would stretch the sidebar and squeeze one side of the
diff. While picked holds windows at a fixed size it lowers the option to fit
them, and restores your value the moment it no longer needs to. A value
smaller than the panes is left alone.

`diff.view` applies to previews too, so with "split" set, moving down the file
list shows each change side by side. The cursor stays in the list while you
browse; <CR> moves it into the diff, and `q` in either pane closes the split
and puts it back on the file you were looking at. `]c`/`[c` jump between hunks
in both presentations; only the unified one can stage, because hunk and line
staging need a patch to hand to `git apply`.

The title always names both sides. There is no ambiguous "the diff": a file
that is both staged and modified has two distinct comparisons, and `<Tab>`
switches between them.

LOG                                                          *picked-view-log*

Paged history with a commit graph computed from the parent links. The graph is
dropped on windows narrower than 60 columns, because a readable list beats an
unreadable picture. `L` loads the next page.

`<CR>` opens commit details: full metadata, the message, and the changed files
with their line counts.

BLAME                                                      *picked-view-blame*

`:PickedBlame` opens a blame column beside the file. The two panes are bound
together with Neovim's own 'scrollbind' and 'cursorbind', so they scroll and
move the cursor together **in both directions** — moving in the blame column
moves the code, and vice versa. Mouse wheels, <C-e>, `zz` and search jumps are
all carried across, because none of it is emulated.

The line under the cursor is highlighted in *both* panes, and so is every
other line belonging to the same commit, which is what makes it obvious at a
glance which block of code a blame entry accounts for. Each commit also gets
its own colour in the blame column, so adjacent commits are distinguishable.

Turn any of that off with `blame.sync_cursor`, `blame.highlight_block` and
`blame.color_commits`.

Repeated commits are drawn once per run so the block structure is visible.
`R` re-blames the parent of the commit under the cursor, which walks a line's
history backwards one rewrite at a time.

The highlights use |PickedBlameCurrentLine| and |PickedBlameBlock|; the
per-commit colours reuse the graph palette. Nothing is left on your file
buffer when the view closes.

`:PickedBlameLine` toggles a lighter always-on variant: the current line's
commit as virtual text.

9. STAGING                                                     *picked-staging*

picked stages at three granularities. All three go through `git apply`, the
same machinery `git add -p` uses; nothing re-implements what git already does,
and a patch that no longer matches its target is refused rather than
force-fitted.

FILES         `s` in the panel. Uses `git add -A`, so deletions and untracked
              files are handled without special cases.

HUNKS         `s` in the diff view, or `<leader>hs` in a file buffer.

LINES                                                  *picked-line-staging*
              A visual selection in the diff view stages exactly the selected
              patch lines. A visual selection in a file buffer stages the
              selected buffer lines.

              The selection rule: an addition is selected when its own line
              number is inside the range; a deletion is selected when the line
              that now occupies its position is inside the range. That makes a
              visual selection behave the way the signs in the gutter suggest
              it should.

              Unselected additions are dropped from the patch; unselected
              deletions become context, so they survive. The resulting hunk
              header is recomputed from the body, never inherited.

Staging from a modified, unsaved buffer stages the *buffer* content, not what
is on disk. This matches |gitsigns| and is usually what is wanted, but it does
mean the index can briefly differ from the file on disk.

10. CONFLICTS                                                *picked-conflicts*

picked never resolves a conflict for you. It locates the conflicting regions,
shows every version git recorded, and applies exactly the choice you made.

Conflicted files appear in their own panel section with git's own wording:
"both modified", "added by us", "deleted by them", and so on.

`<CR>` on a conflict opens the file with each region highlighted and labelled.
Choices — `o` ours, `t` theirs, `b` both, `B` base, `n` neither — are ordinary
buffer edits, so |u| undoes a wrong one.

`:PickedConflict!` opens the three-way view: OURS and THEIRS as read-only panes
flanking the working copy.

When the merge was recorded with the two-way marker style, the merge base is
still available: `:lua require("picked.ui.conflict").show_base_inline()` rebuilds
the file with diff3 markers using `git merge-file`.

Staging a file that still contains `<<<<<<<` markers is caught and requires an
extra confirmation, because git is happy to record those markers as resolved
content and the mistake is expensive to notice later.

==============================================================================
11. SAFETY                                                      *picked-safety*

Destructive operations confirm by default. Every dialog states what will
change, what is lost, and how to decline. `<Esc>`, `q` and `n` all cancel, and
`<CR>` never confirms a destructive action.

  * Discard shows exactly which files are restored from the index and which
    are deleted from disk — very different amounts of lost work.
  * `git clean` shows the complete list of files it would delete first.
  * Force push uses `--force-with-lease` and `--force-if-includes`.
  * Branch deletion of an unmerged branch requires a second, explicit
    confirmation.
  * Git hooks run normally. Bypassing them is never implicit.
  * Commit signing is left entirely to your git configuration; picked neither
    forces nor suppresses it unless `commit.sign` is set.

git can never block on a terminal prompt or an editor from inside picked:
`GIT_TERMINAL_PROMPT=0` and `GIT_EDITOR=true` are set for every invocation, so
a missing credential is an error you can read rather than a hang.

16. ARCHITECTURE                                          *picked-architecture*
>
    git         parses git, spawns processes, knows nothing about windows
      |
    state       one store per repository, generation-tracked
      |
    operations  confirmation, progress, error reporting, refresh
      |
    ui          panels, rendering, keymaps, mouse
<
Three rules hold the design together:

1. Only `git/command.lua` spawns a process, and arguments are always an argv
   array. No shell, no string interpolation, no injection surface. The child
   environment is rebuilt from scratch so an inherited `GIT_DIR` — set when
   Neovim is launched *by* git as its editor — can never redirect an operation
   to the wrong repository.

2. Only machine-readable git formats are parsed: `status --porcelain=v2 -z`,
   `for-each-ref --format`, `log -z`, `blame --porcelain`, `config -z`. A
   filename containing a space, a quote, a tab, a newline or an emoji
   round-trips intact.

3. The newest observation wins. Every repository carries a generation counter;
   a mutation bumps it, and a status read started beforehand is discarded
   rather than allowed to overwrite fresher state. Concurrent refreshes at the
   same generation are coalesced into one `git status`.

Read-only commands pass `--no-optional-locks`, so picked's background status
polling can never take the index lock out from under a `git commit` you run in
a terminal.

Full detail, including the patch-construction rules behind line-level staging,
is in `doc/ARCHITECTURE.md` in the repository.

17. TROUBLESHOOTING                                    *picked-troubleshooting*

Run |:PickedHealth| first.

Boxes instead of icons~
  Your font has no glyphs. `icons = false`, or `vim.g.have_nerd_font = false`.

"Authentication required" when pushing~
  Terminal prompts are disabled inside Neovim by design, so a credential
  prompt becomes an error rather than a hang. Use a credential helper, an SSH
  agent, or an SSH remote.

A default mapping does nothing~
  Something else already owns that key. picked never overwrites an existing
  mapping. |:PickedHealth| lists every skip; move the whole set with `prefix`
  (|picked-prefix|) or rebind the single entry via `global_keymaps`.

The sidebar jumps to full width~
  It was briefly the only window on screen, and Neovim has to give every
  column to something. `last_window` controls this and defaults to
  "keep_width"; see |picked-config-last-window|.

<C-s> does not commit~
  Your terminal is consuming it for XON/XOFF flow control. Use `:w`.

The panel is empty~
  The current buffer may be outside the repository. |:PickedRefresh|.

Slow on a very large repository~
  Raise `refresh_debounce`, or set `auto_refresh = false` and refresh
  manually. `signs.max_filesize` also limits per-buffer work.

Something failed and the message was too short~
  |:PickedOutput| shows the complete raw output of recent git commands; nothing
  is ever swallowed. |:PickedDebugLog| shows picked's own log — raise
  `log_level` to `"debug"` for more.

18. LIMITATIONS                                            *picked-limitations*

Genuinely not implemented, rather than partially implemented:

  * Interactive rebase todo editing. `git rebase -i` runs and can be
    continued, skipped or aborted, but reordering or squashing commits from a
    todo list inside picked is not supported.
  * Submodules are detected and displayed, never managed. picked will not
    update, initialise or commit inside one.
  * `git bisect` is detected as a repository state but has no UI.
  * Word-level diff highlighting. Diffs are line-based.
  * Partial staging of binary files, which is impossible by construction.
  * Splitting a hunk into smaller hunks, `git add --patch` style. Line-level
    selection covers the same need differently.
